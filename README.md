# Bateria BPM

マイクで拾ったバテリアの音から、リアルタイムにテンポを検出するWebアプリ。
バツカーダ／サンバヘギの練習用に作ってあります（打楽器のみ・音階楽器なしの編成を前提）。

**→ https://mikasadh.github.io/samba-bpm/**

iPhone の Safari で開いてマイクを許可し、「開始」を押すだけです。インストール不要、1ファイル完結、サーバー側の処理はありません（音声は端末の外に出ません）。

## できること

- 巨大なBPM表示と、拍に合わせて回るゲージ
- **目標BPMとのズレ表示**（走り／落ち／ジャスト）
- **BPM推移グラフ**と、平均・最小・最大・開始→現在のドリフト量
- タップテンポ、÷2／×2、ホールド、拍子2/4・4/4の頭合わせ
- 内蔵テスト音源による自己テスト（練習前の動作確認用）

## 検出のしくみ

Stark / Davies / Plumbley の実時間ビートトラッカー **BTrack** と同じ構成を独自に実装しています（アルゴリズムは論文と公開実装の記述に基づく再実装で、コードの流用はしていません）。

1. **オンセット検出関数＝複素スペクトル差分（半波整流）**
   1024点ハン窓・ホップ256（@48kHz で 5.3ms = 172〜188Hz）でFFTし、各ビンについて直前2フレームから位相を線形外挿した予測 `φ̂ = 2φ₋₁ − φ₋₂` と、実際のスペクトルとの複素距離を取る。振幅が増えたビンだけを足し合わせる。
   **振幅だけを見る方式と違い、位相の不連続でも打点を検出できる。** 鳴り続けるスルドの上に次の打点が重なる場面で効く。
2. **適応的しきい値** — 局所平均（前8・後7フレーム）を引いて半波整流
3. **自己相関** → **櫛形フィルタバンク**（周期の1〜4倍を1/3/5/7タップで束ねる）＋**レイリー重み**（想定テンポにピーク）＋直前のテンポ仮説からの遷移重み
4. **周期の精密化** — 使える範囲でいちばん高次の自己相関ピーク（最大4周期ぶん）を放物線補間して割る。lag分解能そのものより細かい精度を得るため
5. **拍位置の予測＝累積スコア法** — `C[i] = 0.1·odf[i] + 0.9·max(C[i−v]·w(v))`（対数ガウス遷移窓、tightness=5）。半拍ごとに累積スコアを1拍先へ外挿し、ガウス期待窓の最大点を次の拍とする

検出範囲は常に2倍未満に保たれるため、倍・半分の取り違えが原理的に起きません。

帯域の重み（設定の「重視する音」）はスルド（〜150Hz）／中域／カイシャ（2kHz〜）の3グループに掛かります。既定は均等です。

### 内蔵テスト音源での実測

3台のスルド（別ピッチ・次の拍まで鳴き続ける）、カイシャの16分、シャカシャカ、タンボリンのテレコテコ、暗騒音、各打点に標準偏差7〜12msの演奏ばらつきを載せた信号で測定:

| 設定テンポ | 検出 | 誤差 | 拍位置の平均ずれ | ばらつき |
|---|---|---|---|---|
| 96 | 95.98 | −0.02 | +16.5 ms | 10.8 ms |
| 132 | 131.70 | −0.30 | +10.9 ms | 7.8 ms |
| 158 | 158.33 | +0.33 | +15.4 ms | 9.6 ms |

拍位置のばらつきは信号に載せた演奏ばらつきとほぼ同じで、実際の打点を追えています。急なテンポ変化（116→140）からの再ロックも確認済み。

## 動作環境

iOS Safari / Chrome / Edge / Firefox。マイクの仕様上 **HTTPS でのみ動作**します（`file://` で開いても動きません）。`AudioWorklet` 非対応の古いブラウザでは `ScriptProcessor` に自動で切り替わります。

## 開発

ビルド不要。`index.html` ひとつだけです。

```sh
python -m http.server 8781
# http://127.0.0.1:8781/ を開く（localhost は HTTPS 扱いなのでマイクが使えます）
```

設定 → 自己テストで、内蔵のサンバ風パターン（スルド＋カイシャ16分＋タンボリン）を鳴らして検出精度を確認できます。
